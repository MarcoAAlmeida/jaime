# Behind the scenes

A signed-in-only page — partly because it's the simplest real thing to
gate, partly because build notes are more interesting to people who've
bothered to make an account.

## The stack

- **Nuxt 4** on **Cloudflare Workers** (Nitro's `cloudflare-durable`
  preset). One Worker serves the SSR app, the static assets, and the
  realtime WebSocket relay.
- **Nuxt UI v4** for the component layer; the visual identity (rust
  primary, beige / graphite surfaces) lives in `design/tokens/` and is
  wired into Nuxt UI via a `@theme` block.
- **Durable Objects** hold each JAM room's live state; **D1** holds the
  durable stuff — `@nuxt/content`'s docs in one database, the Catalog
  context (patterns, and now accounts) in another.
- **Strudel** is the live-coding language JAM and the pattern library
  speak. Audio runs entirely in the browser.
- Auth is passwordless: you get an emailed link, it starts a
  server-side session, no passwords are stored.

## How a change happens

Every feature goes through the same loop, tracked with
[OpenSpec](https://github.com/Fission-AI/OpenSpec):

1. **`spec:`** — a proposal, capability spec deltas, a design doc, and a
   task list are written and committed *before any code changes*.
2. **`impl:`** — the tasks are worked through, with tests, and it's
   verified locally and then live.
3. **archive** — the spec deltas are merged into the living
   `openspec/specs/`, and the change moves to `openspec/changes/archive/`.

So the `openspec/specs/` directory is always the current contract for
what the system does, and `openspec/changes/archive/` is the paper
trail of how it got there.
