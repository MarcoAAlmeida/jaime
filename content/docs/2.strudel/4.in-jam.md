# Strudel in JAM

JAM runs Strudel in your browser — no server-side audio. The engine is
assembled from a subset of Strudel's own packages, so most patterns
from [strudel.cc](https://strudel.cc) work unchanged, but not all of it
is wired up.

## What's loaded

- **`@strudel/core` + `@strudel/mini`** — the pattern engine and the
  [mini-notation](/docs/strudel/mini-notation) parser.
- **`@strudel/tonal`** — `.scale()`, `.voicing()`, chord and note
  names.
- **`@strudel/webaudio`** — the audio output, the built-in synth voices
  (`sine`, `sawtooth`, `square`, `triangle`), and the
  `tidalcycles/dirt-samples` bank.

That covers rhythm, mini-notation, notes and scales, the core
transforms (`fast`, `rev`, `every`, `sometimesBy`, `off`, …), signals,
and the standard effects chain (filters, reverb, delay, envelope,
`speed`, …).

## What JAM leaves out

- **Visuals** — Hydra, `punchcard()`, the piano-roll, `.color()` and
  other draw-only calls. Audio only.
- **Custom sample banks** — you get `dirt-samples`; you can't
  `samples('github:…')` your own set from a track.
- **MIDI / OSC / external I/O** — no `.midi()` output.
- **One pattern per track** — each JAM track is a single Strudel
  expression. Structuring a whole arrangement in one track (with
  `arrange`, `cat` of long sections) works, but the collaborative model
  expects one player, one part.

## Tempo is shared

On strudel.cc each pattern sets its own cycle length with `setcps` /
`setcpm`. In JAM the room's transport owns tempo: every track's
playback is aligned to a shared cycle boundary so the parts lock
together. Change tempo from the transport bar, not from inside a
pattern — a per-pattern `setcps` fights the shared clock and drifts.

## Starting points

The [pattern library](/app/patterns) is a catalog of Strudel snippets
that all evaluate on this exact engine — every one has a **Preview**
button and a **Load into JAM** button.
